## 1. 先建立直觉:量化就是"用粗刻度的尺子量东西"

你有一把无限精细的尺子(FP32,能表示几乎任意实数),现在要换成一把只有 256 个刻度的尺子(INT8,\([-128, 127]\))。

量化要解决的核心问题就一个:**怎么把一段连续的实数区间,映射到 256 个整数格子里,使得"还原回来"时误差最小。**

```
原始 FP32 权重(连续):
 -0.42 ────────●──────────●────────●──── 0.38
               ↓ 量化(round 到最近的格子)
INT8 整数(离散,256 格):
 -128 ┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊┊ 127
```

注意两件事:
- 量化是**有损**的——多个相近的浮点数会被 round 到同一个整数格子,信息丢了。
- 量化是**可逆但不精确**的——能从整数"反量化"回浮点,但回来的值和原值有偏差,这个偏差就是**量化误差**。

> 一句话总结量化的本质:**用一个仿射变换(线性缩放 + 平移),把浮点区间压进整数区间,再用同一个变换还原。** 整个 Module 5 所有花哨的算法(GPTQ/AWQ/FP8),底层都是在这个仿射变换上做文章。

**对照你的 MindSpore Lite 经验**:你做黑盒量化时喂进去一批校准数据,工具帮你"统计了数据范围、算了 scale"。校准数据的作用就是确定上面那段"实数区间"的边界(min/max),这一课我们就把它手算一遍。

## 2. 定点表示:整数怎么"假装"自己是小数

CPU/GPU 原生的整数运算没有小数概念。量化的核心技巧叫**定点表示(fixed-point)**:约定一个固定的缩放因子 `scale`,让整数 `q` 代表的真实值是 `q × scale`。

举个最简单的例子。设 `scale = 0.01`:

| 整数 q | 代表的真实值 (q × scale) |
|---|---|
| 5 | 0.05 |
| 100 | 1.00 |
| -37 | -0.37 |

这就是"定点"——小数点的位置由 `scale` 固定下来了。整数本身只是个"几格"的计数,乘上每格多大(scale),就得到真实值。

**这与浮点的根本区别**:浮点(FP32)的小数点是"浮动"的(指数位决定),每个数自带精度;定点的小数点是"钉死"的,所有数共享一个 scale。定点放弃了灵活性,换来了"用便宜的整数运算单元就能算"。

## 3. 仿射量化:scale 与 zero-point 的完整推导

只用 scale 还不够。看一个问题:如果一组权重的范围是 \([0.2, 0.9]\)(全是正数,且不含 0),用"整数 × scale"表示会浪费掉一半整数区间(负整数全用不上)。

解决办法是再加一个**零点(zero-point)** `z`,做一次平移。这就是**仿射量化(affine quantization)**,核心两个公式:

**量化(浮点 → 整数)**:
\[
q = \text{round}\left(\frac{x}{s}\right) + z
\]

**反量化(整数 → 浮点)**:
\[
\hat{x} = s \cdot (q - z)
\]

其中:
- \(x\):原始浮点值
- \(s\):scale(每格代表多大,正实数)
- \(z\):zero-point(浮点 0 对应的整数格子,整数)
- \(q\):量化后的整数
- \(\hat{x}\):反量化还原值(≈ x,但有误差)

### 怎么求 s 和 z?

给定要量化的浮点范围 \([x_{\min}, x_{\max}]\),要映射到整数范围 \([q_{\min}, q_{\max}]\)(INT8 非对称通常是 \([-128, 127]\) 或 \([0, 255]\))。

我们要让区间端点对齐:\(x_{\min} \to q_{\min}\),\(x_{\max} \to q_{\max}\)。这是两个线性方程,解出来:

\[
s = \frac{x_{\max} - x_{\min}}{q_{\max} - q_{\min}}
\]

\[
z = q_{\min} - \text{round}\left(\frac{x_{\min}}{s}\right)
\]

直觉:`s` 就是"总跨度 ÷ 格子数",即每格多大;`z` 是平移量,保证浮点的某个值能精确对齐到整数格子。

> **为什么 z 要取整(round)?** 因为 z 必须是整数——它代表"哪个整数格子对应浮点 0"。如果 z 不是整数,反量化时浮点 0 就无法被精确表示,而 0 在神经网络里极其常见(padding、ReLU 输出、稀疏权重),必须能被无误差表示。这个细节叫 **zero-point 必须可精确表示 0**,是仿射量化设计的关键。

---

## 4. 对称量化 vs 非对称量化

上面那套带 zero-point 的是**非对称量化**。还有一种更简单的**对称量化**:强制 `z = 0`,即不做平移。

### 对称量化

强制零点为 0,只用一个 scale。此时取 \([x_{\min}, x_{\max}]\) 的绝对值最大值 \(A = \max(|x_{\min}|, |x_{\max}|)\),映射到对称整数区间 \([-127, 127]\):

\[
s = \frac{A}{127}, \qquad q = \text{round}\left(\frac{x}{s}\right), \qquad \hat{x} = s \cdot q
\]

```
对称量化(z=0,区间关于 0 对称):
        -A        0        +A
         |--------|--------|        浮点
      -127        0       127       整数

非对称量化(z≠0,区间可任意偏):
       xmin              xmax
         |----------------|          浮点
      -128       z        127        整数(z 落在浮点 0 处)
```

### 怎么选?一张表说清

| | 对称量化 | 非对称量化 |
|---|---|---|
| zero-point | 固定 = 0 | 需要计算 |
| 计算开销 | 小(无平移项) | 大(矩阵乘要展开 z 的交叉项) |
| 适合的数据 | 分布关于 0 对称(如**权重**) | 分布偏向一侧(如 **ReLU 后的激活**,全 ≥ 0) |
| 整数利用率 | 数据偏时浪费一半 | 充分利用 |

**关键结论**:
> **权重通常用对称量化**(权重分布天然接近以 0 为中心的钟形),**激活常用非对称量化**(尤其经过 ReLU/GELU 后偏向一侧)。这也是为什么后面会反复看到 "W8A8"(权重对称、激活非对称)这类组合。

为什么对称量化在矩阵乘里更快?展开非对称的反量化代入 \(Y = XW\):每个乘积项 \((q_x - z_x)(q_w - z_w)\) 会产生 \(q_x q_w, -q_x z_w, -z_x q_w, z_x z_w\) 四项,后三项是额外的"交叉项"开销。对称量化 \(z=0\),只剩 \(q_x q_w\) 一项,干净利落。这是工程上权重几乎总用对称量化的现实原因。

## 5. 量化粒度:per-tensor / per-channel / per-group

一个 scale 管多少个数?这就是**粒度**问题,直接决定精度。

```
一个权重矩阵 W (out_features × in_features):

per-tensor:        per-channel(按输出通道):   per-group(每 128 个一组):
整个矩阵 1 个 s     每一行 1 个 s               每行再切成若干组,每组 1 个 s
┌──────────┐       ┌──────────┐ s0            ┌───┬───┬───┐
│          │       ├──────────┤ s1            │s00│s01│s02│
│    s      │       ├──────────┤ s2            ├───┼───┼───┤
│          │       ├──────────┤ s3            │s10│s11│s12│
└──────────┘       └──────────┘ ...           └───┴───┴───┘
精度最低           中等                        精度最高
开销最小           开销中等                    开销最大(scale 多)
```

为什么粒度越细越准?**因为不同通道/分组的数值范围可能差很多。** 假设一个矩阵里 99% 的权重在 \([-0.1, 0.1]\),但有一行的权重在 \([-2, 2]\)。如果用 per-tensor,scale 被那一行的大值"撑大",于是那 99% 的小权重全被挤进很少几个整数格子里,精度灾难性下降。per-channel/per-group 让每块用自己合适的 scale,互不拖累。

| 粒度 | scale 数量 | 精度 | 典型用途 |
|---|---|---|---|
| per-tensor | 1 | 最低 | 激活量化(简单、快) |
| per-channel | 通道数 | 高 | 权重量化(标配) |
| per-group | 通道数 × 组数 | 最高 | 低比特权重量化(INT4,group=128) |

> **记住这个权衡**:scale/zero-point 本身也要占存储(FP16),粒度越细,这些"元数据"越多。INT4 量化常用 group=128,就是在"精度"和"scale 存储开销"之间取的经典平衡点。后面 GPTQ/AWQ 默认都是 group=128 的 per-group。

## 6. 量化误差从哪来

把量化-反量化连起来看,误差有两个来源:

**① 舍入误差(rounding error)**:`round()` 把浮点拍到最近的整数格,最大偏差是半格,即 \(\pm s/2\)。这是**均匀分布**的小噪声,粒度越细(s 越小)误差越小。

**② 截断/饱和误差(clipping error)**:如果某个值超出了 \([x_{\min}, x_{\max}]\)(比如校准时没见过的离群值 outlier),它会被**钳位(clamp)**到边界,这个误差可能非常大。

```
            被 clip(大误差)        正常 round(小误差)
                ↓                        ↓
 真实分布: ░░░░░░░██████████████████░░░░░░●(outlier 落在量化范围外)
                  └── 量化范围 ──┘     被拉回到 xmax
```

这里有一个**根本性的矛盾**:
> 为了少 clip,你想把范围 \([x_{\min}, x_{\max}]\) 取大一点(包住 outlier);但范围越大,scale 越大,正常值的舍入误差就越大。**outlier 越极端,这个矛盾越尖锐。** 这正是大模型激活量化最大的痛点——Transformer 的激活里存在少数幅度极大的离群通道(后面 L4 的 SmoothQuant/AWQ 就是专门治这个的)。

校准(calibration)的本质,就是在"clip 误差"和"round 误差"之间找一个最优的范围(比如不取绝对 min/max,而是取 99.9% 分位点,或用 KL 散度最小化),这是 L2 的主题。

## 7. 呼应 Roofline:为什么减少 bit 数能加速 decode

回到 Module 1 L1 埋下的伏笔。大模型 decode 阶段(一次生成一个 token)是**带宽受限**的:每生成 1 个 token,要把**整个模型的权重**从显存读一遍,而计算量极小(就一个 token 的乘加)。

decode 的耗时近似:

\[
T_{\text{decode}} \approx \frac{\text{模型权重总字节数}}{\text{显存带宽}}
\]

权重从 FP16(2 字节)量化到 INT4(0.5 字节),**要搬运的字节数直接降到 1/4**,而显存带宽不变,所以 decode 理论上能快近 4 倍。

```
FP16 权重:每个 token 要读 14 GB(7B 模型) ──→ 慢
INT4 权重:每个 token 只读 3.5 GB           ──→ 快 ~4×
              ↑
        瓶颈是"读字节",不是"算"
```

> **这是量化在 LLM 推理里的头号价值**:不是为了省显存(那是附带好处),而是因为 decode 卡在带宽上,**减少要读的字节数 = 直接减少 decode 时间**。理解这一点,你就懂了为什么 LLM 量化的主流是"只量化权重(W4A16)"——权重是带宽大头,激活反而可以保持 FP16。

注意:prefill 阶段是计算受限的(并行处理整个 prompt),量化对 prefill 的加速远不如 decode 明显。这个区别在 L5 讲 FP8 时还会再用到。

5. 为什么权重多用对称量化,而 ReLU 后的激活多用非对称量化?

<details>
<summary>参考答案(想完再看)</summary>

1. 对称取 \(A = \max(|-0.6|, |0.4|) = 0.6\),\(s = 0.6 / 127 ≈ 0.004724\)。浮点 0.1:\(q = \text{round}(0.1 / 0.004724) = \text{round}(21.17) = 21\)。

3. 因为 0 在网络里大量出现:ReLU 把负值全置 0、padding 是 0、稀疏权重是 0、attention mask 用 0。如果 0 反量化后变成一个小非零值(如 0.002),这些"本该是 0"的地方会引入系统性偏差,且大量累加后误差被放大。所以 zero-point 必须是整数,保证浮点 0 ↔ 整数 z 精确对应。

4. FP16:\(14\text{GB} / 2\text{TB/s} = 7\text{ms/token}\)(理论下限,约 143 token/s)。INT4:权重降到 3.5GB,\(3.5/2000 = 1.75\text{ms/token}\)(理论约 571 token/s)。实际有其他开销达不到,但量级关系成立。

5. 权重分布近似以 0 为中心对称的钟形,对称量化既匹配分布又省去 zero-point 交叉项开销,矩阵乘更快;ReLU/GELU 后的激活全部 ≥ 0(或强烈偏向一侧),若用对称量化会浪费整个负半区(一半整数格子用不上),非对称量化能把范围精确贴合 \([0, x_{\max}]\),充分利用所有格子。

## 小结

- 量化的数学本质是**仿射变换**:量化 \(q = \text{round}(x/s) + z\),反量化 \(\hat{x} = s(q - z)\)。
- **scale** = 总跨度/格子数(每格多大);**zero-point** = 让浮点 0 精确对齐整数格的平移量(必须是整数)。
- **对称量化**(z=0)用于权重,矩阵乘更快;**非对称量化**用于偏向一侧的激活。
- 粒度 **per-tensor < per-channel < per-group**,越细越准但 scale 元数据越多;INT4 标配 per-group(group=128)。
- 误差两来源:**舍入误差**(±s/2,均匀小噪声)和 **截断误差**(outlier 被钳位,可能很大),二者存在范围取大/取小的根本矛盾。
- 呼应 roofline:decode 带宽受限,**量化减少要搬运的字节数,直接加速 decode**,这是 LLM 量化的头号动机,也是 W4A16 流行的原因。
