# M5 · Lesson 3:GPTQ 原理与实战

> 前两课你知道了"怎么量化一个张量"和"PTQ 靠校准"。但最朴素的 PTQ 是 **round-to-nearest(RTN,四舍五入到最近格)**——每个权重独立取整,互不商量。GPTQ 是个聪明得多的 PTQ:它问了一个 RTN 从没问过的问题——**"我把这个权重取整造成的误差,能不能让旁边还没量化的权重补偿回来?"** 这个"误差补偿"的思想,加上二阶 Hessian 信息,就是 GPTQ 能把 INT4 量化做到几乎不掉点的核心。
> 预计用时:3 小时(理论较硬 + 实战需 N 卡)。
> 前置:L1(量化公式)、L2(PTQ/校准)、线性代数(矩阵求逆、二次型)。

## 1. RTN 的局限:每个权重"各自为政"

回顾 L1/L2 的朴素量化:对权重矩阵 \(W\),逐元素 \(q = \text{round}(w/s)\)。这就是 **RTN(round-to-nearest)**。

RTN 的隐含假设是:**每个权重的量化误差互相独立、且对输出的影响一样大。** 这两点都不成立:

- 权重不是孤立的,它们一起参与矩阵乘 \(Y = WX\),误差会**叠加**影响输出;
- 不同权重对输出的影响**不一样大**——有的权重乘的是大激活,量化它误差被放大;有的乘小激活,量化它无所谓。

```
RTN 的视角:                     GPTQ 的视角:
w1 → round → 完事               w1 → round(有误差 e1)
w2 → round → 完事                   ↓ 把 e1 "记账"
w3 → round → 完事               调整 w2,w3 的量化目标去抵消 e1
(各自取整,误差累积没人管)       (后量化的权重补偿前面的误差)
```

> **一句话抓住 GPTQ 的灵魂**:RTN 是"独立取整,误差自生自灭";GPTQ 是"边量化边补偿,让后量化的权重吸收前面量化产生的误差"。这就是"逐层误差补偿"。

---

## 2. GPTQ 的优化目标:逐层重构误差最小

GPTQ 不追求"量化后权重最接近原权重",而追求**"量化后这一层的输出最接近原输出"**。对一个线性层,目标是:

\[
\arg\min_{\widehat{W}} \; \big\| WX - \widehat{W} X \big\|_2^2
\]

其中 \(W\) 是原权重,\(\widehat{W}\) 是量化后权重(每个元素被限制在量化格点上),\(X\) 是校准数据在这一层的输入激活。

**为什么是"输出接近"而不是"权重接近"?** 因为我们真正在乎的是模型行为不变,而模型行为由**输出**决定。两个权重值差一点点,如果它乘的激活很小,对输出几乎没影响——那就不值得为它牺牲精度。这个目标天然地把"权重重要性"和"激活大小"耦合进来了。

这个目标函数最早来自一个经典思想:**OBS(Optimal Brain Surgeon,最优脑外科)**——本是用于剪枝(删哪个权重对 loss 影响最小),GPTQ 把它迁移到量化(把权重"挪到"量化格点对输出影响最小)。

---

## 3. Hessian:谁更"敏感",它说了算

上面那个二次型目标,对 \(\widehat W\) 求二阶导,就得到 **Hessian 矩阵**。对逐层重构目标 \(\|WX - \widehat W X\|^2\),Hessian 正比于:

\[
H = 2 X X^\top
\]

\(XX^\top\) 是激活的**自相关矩阵**(也叫二阶统计量)。它的含义非常直观:

- **对角线 \(H_{ii}\)**:第 \(i\) 个输入维度激活的能量(\(\sum x_i^2\))。能量大 = 这个维度激活大 = 对应权重量化误差被放大得厉害 = 它更"敏感",量化要更小心。
- **非对角 \(H_{ij}\)**:第 \(i\)、\(j\) 维激活的相关性。相关性告诉我们"调整权重 j 能多大程度补偿权重 i 的误差"。

```
H = X Xᵀ 的含义:
┌─────────────────────────┐
│ H_ii 大 → 该列激活强      │  → 这一列权重量化要谨慎
│ H_ij    → 列 i,j 的关联   │  → 量化 i 后,按关联调整 j 来补偿
└─────────────────────────┘
```

> **关键洞察**:Hessian = 激活的二阶统计 \(XX^\top\)。它一举编码了两件 RTN 完全忽略的事:① 哪些权重重要(对角线)② 权重之间如何互相补偿(非对角)。GPTQ 之所以远胜 RTN,本质就是**用上了这份二阶信息**。

(校准数据在这里的作用又出现了:它就是用来估计 \(XX^\top\) 的——这也是 GPTQ 属于 PTQ 的原因。)

## 4. GPTQ 算法:逐列量化 + 误差补偿(直觉版)

完整推导很长,这里给你能"讲明白"的直觉 + 关键公式。GPTQ 按列(逐个输入维度)从左到右量化权重,每量化一列就把误差补偿到右边还没量化的列。

**单步逻辑**(量化第 \(q\) 列):

1. 把第 \(q\) 列权重量化:\(\widehat w_q = \text{quant}(w_q)\),产生误差 \(e = w_q - \widehat w_q\)。

2. 这个误差会污染输出。用 Hessian 的逆,把误差**最优地分摊**到右边所有未量化的列上,更新它们:

\[
w_j \leftarrow w_j - e \cdot \frac{H^{-1}_{qj}}{H^{-1}_{qq}} \quad (j > q)
\]

直觉:\(H^{-1}\) 告诉我们"权重之间怎么互相代偿最划算"。第 \(q\) 列取整丢了点东西,就让和它相关的后续列各自微调一点,把这个"亏空"在输出层面补回来。

3. 量化下一列,重复。越往后的列,身上背着前面所有列累积传过来的"补偿账",所以它们量化时目标已经被调整过了。

```
量化顺序(逐列从左到右):
列1  列2  列3  列4 ...
 ▼
量化列1 → 误差 e1 → 按 H⁻¹ 分摊给 列2,列3,列4...(调整它们的待量化目标)
      量化列2 → 误差 e2 → 分摊给 列3,列4...
            量化列3 → ...
(每一步:取整 → 算误差 → 用 Hessian 逆补偿到右侧未量化列)
```

**为什么这比 RTN 好?** RTN 让每列误差独立累积,输出误差是所有列误差的"无补偿叠加";GPTQ 让每列误差被后续列主动吸收,输出误差被持续压低。在 INT4 这种误差较大的低比特下,补偿带来的精度差距非常显著——这就是 GPTQ 能在 INT4 下保住精度、而 RTN 明显掉点的原因。

工程上 GPTQ 还有几个实现要点(了解即可):
- **Cholesky 分解**稳定地求 \(H^{-1}\)(直接求逆数值不稳);
- **阻尼(damping)**:给 \(H\) 对角加一个小量 \(\lambda\),防止矩阵奇异;
- **逐块(block)处理**列,平衡速度与精度;
- **act-order(g_idx)**:按 Hessian 对角线大小(激活重要性)排序量化顺序,先量化重要列,精度更好(代价是推理时有重排开销)。

## 5. GPTQ 在生态里的位置

| 维度 | 说明 |
|---|---|
| 类型 | PTQ(训练后,需校准数据估 Hessian) |
| 量化对象 | **只量化权重**,典型 W4A16(权重 INT4,激活 FP16) |
| 粒度 | per-group(常用 group=128)对称/非对称 |
| 强项 | INT4 下精度高,量化速度快(单卡几十分钟~几小时) |
| 工具 | AutoGPTQ、GPTQModel,vLLM/TGI 可直接加载 GPTQ 权重推理 |
| 对照 | 比 RTN 准很多;与 AWQ(L4)是当前 W4A16 两大主流 |

> 呼应 L1:GPTQ 是 W4A16,正中"decode 带宽大头是权重"的靶心——量化权重把每 token 要读的字节降到 1/4,decode 显著加速,而激活保持 FP16 避开了 outlier 的麻烦。

## 练习题

1. 为什么 GPTQ 的优化目标是"输出 \(WX\) 接近"而不是"权重 \(W\) 接近"?这带来什么好处?
2. Hessian \(H = XX^\top\) 的对角线和非对角线分别编码了什么信息?
3. 简述 GPTQ 单步"量化一列 + 补偿"在做什么,为什么需要 \(H^{-1}\)?
4. GPTQ 是 W4A16,为什么不顺便也量化激活成 W4A4?
5. act-order(按激活重要性排序量化)为什么能提升精度?它有什么代价?

<details>
<summary>参考答案(想完再看)</summary>

1. 因为我们真正在乎的是模型**行为(输出)**不变,而非权重数值本身。以输出为目标,会自动把"权重重要性"和"它乘的激活大小"耦合进来:乘小激活的权重即使量化误差大,对输出影响也小,不必为它牺牲;以输出为目标能把量化预算花在真正影响输出的权重上。

2. 对角 \(H_{ii} = \sum x_i^2\) 是第 i 个输入维度激活的能量,代表该列权重的"敏感度"(激活越大,量化误差被放大越多);非对角 \(H_{ij}\) 是 i、j 两维激活的相关性,代表"调整列 j 能多大程度补偿列 i 的误差"。

3. 量化某列产生误差 e,然后用 \(H^{-1}\) 把 e 最优地分摊到右侧未量化的列(\(w_j \leftarrow w_j - e \cdot H^{-1}_{qj}/H^{-1}_{qq}\)),让这些列各微调一点,在**输出层面**把 e 造成的偏差抵消掉。需要 \(H^{-1}\) 是因为它编码了列与列之间"如何代偿最划算"的二阶关系——这是最小化二次型目标的解析解形式。

4. 因为激活有 outlier 通道,极难量化(L2 讲过),W4A4 精度会严重崩;而 decode 的带宽瓶颈主要在权重,量化权重就拿到了大部分加速收益。所以主流是 W4A16,把激活留在 FP16 规避 outlier。

5. 先量化"重要列"(Hessian 对角线大的),此时还有大量未量化列可以吸收它的误差,补偿空间大、效果好;若把重要列留到最后,能补偿它的列已所剩无几。代价:推理时权重列被重排,需要额外的 g_idx 索引/重排开销,略微拖慢且增加实现复杂度。

</details>

## 小结

- **RTN 太傻**:逐元素独立取整,忽略了"误差会叠加影响输出"和"权重重要性不同"两件事。
- **GPTQ 的目标**是逐层**输出重构误差最小** \(\|WX - \widehat WX\|^2\),天然耦合权重重要性与激活大小。
- **Hessian \(H = XX^\top\)** 是激活二阶统计:对角线 = 敏感度,非对角 = 代偿关系,这是 GPTQ 超越 RTN 的信息来源。
- **算法核心**:逐列量化,每列取整后用 \(H^{-1}\) 把误差补偿到右侧未量化列;辅以 Cholesky、阻尼、act-order 等工程技巧。
- GPTQ 是 **W4A16 PTQ**,正中 decode 带宽瓶颈,是当前主流量化方案之一(另一个是 L4 的 AWQ)。
