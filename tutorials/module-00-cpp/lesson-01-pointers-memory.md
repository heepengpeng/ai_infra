## 1. 先破除一个 Python 幻觉:变量到底是什么

在 Python 里你写:

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)   # [1, 2, 3, 4] —— a 也变了!
```

你早就知道:`a` 和 `b` 是**贴在同一个对象上的两张名字标签**(reference)。变量名不"拥有"数据,只是指向它。Python 里几乎一切都是这种"引用语义",内存由 GC 自动回收,你从不关心一个对象住在哪、占多少字节。

C++ 的世界观**截然相反**:

> 在 C++ 里,**变量就是一块有名字、有固定地址、有固定大小的内存**。`int a = 10;` 的意思是"划出 4 字节内存,起名叫 `a`,往里写 10"。赋值默认是**拷贝整块内存**,不是贴标签。

看这段对照:

```cpp
int a = 10;
int b = a;   // 把 a 的 4 字节"复制"一份给 b。从此 a、b 是两块独立内存
b = 20;
// 此时 a 仍是 10,b 是 20。改 b 不会动 a
```

```
Python(引用语义)              C++(值语义,默认拷贝)
                              
 a ──┐                         a: [ 10 ]   ← 一块内存
     ├──> [1,2,3]              b: [ 10 ]   ← 另一块独立内存(a 的副本)
 b ──┘                         
 改 b 就是改同一个对象          改 b 不影响 a
```

| 维度 | Python | C++ |
|---|---|---|
| 变量是什么 | 指向对象的名字标签 | 一块具体的内存 |
| `b = a` 默认行为 | 共享同一对象(引用) | 拷贝整块内存 |
| 谁管内存回收 | GC 自动 | **你自己**(堆内存) |
| 能否拿到"地址" | 拿不到(`id()` 只是个号) | 能,`&a` 就是真实地址 |

记住这个根本差异,后面所有"为什么 C++ 这么麻烦"的问题,根子都在这。

## 2. 指针:一个存"地址"的变量

既然每块内存都有地址,那我们就能用一个变量专门**存地址**——这就是指针。

```cpp
int a = 10;
int* p = &a;   // & 取 a 的地址,p 是"指向 int 的指针",存着 a 的地址
*p = 20;       // * 解引用:顺着地址找到那块内存,改它。现在 a == 20
```

两个符号必须分清(它们是互逆操作):

- `&a`:**取地址**(address-of)。"告诉我 `a` 住在哪。"
- `*p`:**解引用**(dereference)。"顺着 `p` 存的地址,把那块内存的值取出来/写进去。"

```
内存示意(地址是假设值):

地址      内容
0x7ff0:  [  20  ]  ← a 这块内存(被 *p = 20 改成了 20)
  ▲
  │
0x7ff8:  [0x7ff0]  ← p 这块内存,里面存的是 a 的地址
```

> 类比:`a` 是一栋房子,`&a` 是这栋房子的门牌号,`p` 是写着门牌号的便利贴,`*p` 是"按便利贴上的门牌号找过去,进屋办事"。

**为什么需要指针?** 最直接的理由:让函数能修改外部变量,以及高效传递大块数据(不拷贝,只传一个地址)。

## 3. 用函数调用看清:值传递 vs 指针传递 vs 引用传递

这是 Python 工程师最容易栽跟头的地方。看 `code/pointers_demo.cpp`:

```12:23:/Users/hp/010Code/007Python/001Learn/ai_infra/tutorials/module-00-cpp/code/pointers_demo.cpp
    int a = 10;

    add_one_by_value(a);
    printf("after by_value:   a = %d\n", a);   // 仍是 10

    add_one_by_pointer(&a);                    // 显式取地址传进去
    printf("after by_pointer: a = %d\n", a);   // 11

    add_one_by_ref(a);                         // 直接传变量,语法上像值传递
    printf("after by_ref:     a = %d\n", a);   // 12
```

三个函数的定义:

```5:7:/Users/hp/010Code/007Python/001Learn/ai_infra/tutorials/module-00-cpp/code/pointers_demo.cpp
void add_one_by_value(int x)   { x += 1; }       // 改的是副本,外面看不到
void add_one_by_pointer(int* p){ *p += 1; }      // 通过地址改原值
void add_one_by_ref(int& r)    { r += 1; }       // 引用 = 原变量的别名
```

编译运行:

```bash
g++ -std=c++17 -Wall pointers_demo.cpp -o pointers_demo && ./pointers_demo
```

输出:

```
after by_value:   a = 10
after by_pointer: a = 11
after by_ref:     a = 12
```

逐个解释:

- **值传递 `int x`**:函数拿到的是 `a` 的一份拷贝,改 `x` 跟 `a` 毫无关系。这跟 Python 传不可变对象(int)的效果很像,但机制不同(C++ 是真拷贝内存)。
- **指针传递 `int* p`**:你显式把 `a` 的地址传进去,函数 `*p += 1` 顺着地址改到了真正的 `a`。调用处要写 `&a`,函数体要写 `*p`,**啰嗦但意图明确**。
- **引用传递 `int& r`**:`r` 是 `a` 的**别名**(alias),它俩就是同一块内存的两个名字。改 `r` 就是改 `a`。调用处干净(直接写 `a`),不用 `&`。

## 4. 指针 vs 引用:到底用哪个?

它们都能"让函数改外部变量",区别在于约束和语义:

| | 指针 `T*` | 引用 `T&` |
|---|---|---|
| 可以为空吗 | 可以(`nullptr`) | 不行,必须绑定一个已存在对象 |
| 能改指向吗 | 能,`p` 可以重新指别处 | 不能,一旦绑定终身不变 |
| 语法 | 要 `*` 解引用、`&` 取地址 | 像普通变量一样用 |
| 典型用途 | 可选参数、动态数组、需要"换目标" | 给函数高效传大对象、运算符重载 |

经验法则(够用即可):

> **能用引用就用引用(更安全、更干净);当"可能没有值(空)"或"需要改变指向"时,才用指针。**

而在 **CUDA 里你会大量看到裸指针**(`float* d_in`),因为 GPU 显存的地址必须用裸指针表示,`cudaMalloc(&d_in, bytes)` 返回的就是一个指向显存的地址。所以指针这关必须过——这也是本课放在最前面的原因。

```cpp
// 你在 Module 1 已经见过的写法,现在能完全看懂了:
float* d_in;                  // 一个指向显存的裸指针,暂时是野的
cudaMalloc(&d_in, bytes);     // 传 d_in 的地址进去,让它被填上一块显存地址
//        ▲ 这个 & 就是"取 d_in 的地址",好让函数能修改 d_in 本身
```

## 5. 内存的两大区域:栈 vs 堆

程序运行时,内存主要分两块你要关心的区域。理解它们是理解 `new/delete`(以及后面 RAII、`cudaMalloc`)的关键。

```
                  高地址
   ┌────────────────────────────┐
   │            栈 Stack          │  ← 函数局部变量住这。函数调用时"长出来"
   │   ↓ 向下生长                  │     函数返回时"自动收回"。快、自动、容量小
   │                              │
   │         (中间是空的)          │
   │                              │
   │   ↑ 向上生长                  │
   │            堆 Heap           │  ← new/malloc 分配的内存住这。
   └────────────────────────────┘     大、灵活,但必须你手动归还
                  低地址
```

**栈(Stack)**:函数里的局部变量(如 `int a = 10;`)默认放栈上。特点:

- 进函数自动分配,出函数(出作用域)**自动回收**,你完全不用管。
- 极快(就是移动一个栈指针)。
- 但容量小(通常几 MB),且大小必须编译期就基本确定。

**堆(Heap)**:运行时动态申请的内存,用 `new` / `malloc` 拿,用 `delete` / `free` 还。特点:

- 容量大(受限于物理内存/显存),大小可运行时决定。
- **必须手动释放**,否则就是内存泄漏。
- 分配/释放比栈慢。

看 `code/stack_heap.cpp` 的对比:

```17:31:/Users/hp/010Code/007Python/001Learn/ai_infra/tutorials/module-00-cpp/code/stack_heap.cpp
    // ① 栈上分配:出了作用域自动回收,你不用管
    int stack_arr[4] = {1, 2, 3, 4};
    printf("stack_arr[0] = %d (地址在栈上: %p)\n", stack_arr[0], (void*)stack_arr);

    // ② 堆上分配(C 风格 malloc/free)—— CUDA 的 cudaMalloc 就是这个味道
    int* heap_c = (int*)malloc(4 * sizeof(int));
    for (int i = 0; i < 4; ++i) heap_c[i] = i * 10;
    printf("heap_c[2] = %d (地址在堆上: %p)\n", heap_c[2], (void*)heap_c);
    free(heap_c);            // 必须手动还,否则内存泄漏

    // ③ 堆上分配(C++ 风格 new/delete)
    int* heap_cpp = new int[4];
    for (int i = 0; i < 4; ++i) heap_cpp[i] = i * 100;
    printf("heap_cpp[3] = %d\n", heap_cpp[3]);
    delete[] heap_cpp;       // new[] 必须配 delete[],不能配 delete
```

```bash
g++ -std=c++17 -Wall stack_heap.cpp -o stack_heap && ./stack_heap
```

两个铁律,记死:

> **`malloc` 配 `free`,`new` 配 `delete`,`new[]` 配 `delete[]`。配错或不配,轻则泄漏,重则崩溃。**

注意看打印的地址:栈对象的地址和堆对象的地址通常差得很远(一个在高地址区、一个在低地址区),这印证了上面的内存布局图。

## 6. 为什么 C++ 不像 Python 自动回收?

Python 有垃圾回收(GC),帮你跟踪每个对象还有没有人引用,没人用了就回收。代价是:**运行时开销 + 不可控的停顿(STW)+ 你无法精确掌控内存何时释放**。

C++ 的定位是系统级语言,要榨干硬件,所以它把内存管理权**完全交给你**:你说什么时候分配、什么时候释放,零额外开销、完全可控。代价就是——**你必须自己记得释放,而且不能用已释放的内存**。

这带来三类经典 bug(写 CUDA 时同样会遇到显存版本):

| Bug | 含义 | 后果 |
|---|---|---|
| 内存泄漏(leak) | `new` 了忘记 `delete` | 内存越用越多,最终 OOM |
| 悬垂指针(dangling) | 用了已经 `delete` 的内存 | 读到垃圾值或崩溃 |
| 重复释放(double free) | 同一块内存 `delete` 两次 | 崩溃 |

> 好消息:这些痛点正是 **Lesson 3 的 RAII + 智能指针**要解决的——让"释放"自动发生,把 C++ 的安全性拉回接近 Python 的水平,同时保留零开销。本课先理解"为什么需要手动管理",才能体会智能指针的价值。

## 练习题

1. 下面这段代码错在哪?会发生什么?

```cpp
int* p = new int(5);
delete p;
printf("%d\n", *p);   // ???
```

<details><summary>参考答案</summary>

`delete p` 之后,`p` 指向的内存已经还给系统,但 `p` 这个指针变量本身还存着那个(已失效的)地址——这就是**悬垂指针**。`*p` 是在读已释放的内存,属于**未定义行为(UB)**:可能打印出 5(内存还没被覆盖),可能打印垃圾值,也可能直接崩溃。正确做法是释放后把指针置空:`delete p; p = nullptr;`,这样后续误用会立刻空指针崩溃(比读到垃圾值更容易定位)。
</details>

2. 引用能不能"不绑定任何东西"?下面这行能编译吗?

```cpp
int& r;   // 没有初始化
```

<details><summary>参考答案</summary>

**不能编译**。引用必须在定义时就绑定到一个已存在的对象,且终身不变。这正是引用比指针安全的地方:不存在"空引用"或"野引用"(语言层面禁止)。指针则可以是 `nullptr` 或未初始化的野指针。
</details>

3. 用 Python 的思维解释:为什么 C++ 里 `int b = a;` 之后改 `b` 不会影响 `a`,但 Python 里 `b = a`(a 是 list)之后改 `b` 会影响 `a`?

<details><summary>参考答案</summary>

C++ `int b = a` 是**值语义**:把 `a` 的内存内容拷贝一份给 `b`,两块内存独立。Python `b = a` 是**引用语义**:`b` 和 `a` 是贴在同一个 list 对象上的两张标签,没有发生拷贝,所以通过任一标签修改都影响同一对象。要在 Python 得到 C++ 那种独立副本,得显式 `b = a.copy()`(或 `copy.deepcopy`)。
</details>

4. `cudaMalloc(&d_in, bytes)` 为什么参数是 `&d_in`(指针的地址)而不是 `d_in`?

<details><summary>参考答案</summary>

因为 `cudaMalloc` 的职责是**分配一块显存、并把这块显存的地址写回给你的指针变量 `d_in`**。要让函数能修改 `d_in` 本身(给它赋一个新地址),就得把 `d_in` 的地址(`&d_in`,类型是 `float**`)传进去——这正是第 3 节"指针传递才能修改外部变量"的应用。如果只传 `d_in`(值传递),函数改的是副本,你的 `d_in` 还是野指针。
</details>

## 小结

- C++ 变量是**有地址的一块内存**,赋值默认**拷贝**(值语义);Python 变量是**名字标签**,赋值默认**共享**(引用语义)。这是一切差异的根源。
- `&` 取地址,`*` 解引用;**指针**是存地址的变量,可空、可改指向;**引用**是别名,不可空、不可改绑。能用引用就用引用。
- 局部变量在**栈**(自动回收),`new`/`malloc` 在**堆**(必须手动 `delete`/`free`)。
- 手动管理带来三类经典 bug:泄漏、悬垂、重复释放;`-fsanitize=address` 是抓它们的利器。
- 这套指针 + 手动内存的认知,直接迁移到 CUDA 的 `cudaMalloc`/`cudaFree`/显存指针。
